- This project uses UTM to create or clone macOS virtual machines, then performs fixed automation steps inside those VMs.
- Feishu bot is the required source of submission registration data and workflow triggers. Use the project Feishu bot runtime/API files or endpoints to obtain registration data; do not use the Feishu desktop app as the data source unless the user explicitly asks to operate it.

## Project Memory

- Project name/purpose: UTM macOS submission automation. The workflow scope is exactly the live 31-skill ordered list below and no external skill family.
- Runtime environment: host macOS creates/clones UTM macOS VMs under `${SUBMISSION_VM_IMAGES_DIR}` from `${SUBMISSION_VM_TEMPLATE}`; both are resolved from the current host configuration, not a copied host path.
- Submission data source: the local project Feishu bot service in `services/` and `runtime/`, especially `runtime/feishu-runs.json` or Feishu message history fetched through the bot API. Do not scrape the Feishu desktop app for data. Initial bank data is optional and is never recovered from Feishu/runtime later: `utm-20` reads ABA routing and account numbers from the matching Notion page's live `账号信息` code block through `scripts/notion_api.py`; `utm-21` inherits the current UTM-20 context and reads `代码链接：`, `正式包名: `, and `APP_ID：` through the same API without re-reading a run file.
- Fixed skill order after Feishu receives submission data:
  1. Feishu bot creates the submission run and unique lowercase four-letter `vm_name`.
  2. `notion-utm`: use the Notion API to create `<应用名>-<虚拟机名称>` from the current host page's unique `模板` child and fill `账号信息` only. For non-bank data, parent/template ambiguity, conflicts, or readback failures, reparse the same run, perform bounded live reads, roll back reversible writes from before evidence, and independently re-read. Only exhausted or externally unrepairable states use the original-chat last fault card. Missing initial bank data remains valid.
  3. `notion-utm-1`: read the fixed Feishu table/view, then fill `应用信息` by Notion API. A confirmed API-context mismatch records `FEISHU_TABLE_CONTEXT_MISMATCH=verified`, stops the Notion write, and must be repaired in the project skill or script before continuing. Only persistent authoritative-data faults use the last fault card. Existing Notion conflicts are rebuilt from the fresh unique row, replaced automatically and read back exactly; category normalization has no user-choice branch.
  4. `utm-clone-macos`: resolve the fixed template from `${SUBMISSION_VM_TEMPLATE}` and clone it to `${SUBMISSION_VM_IMAGES_DIR}/<vm_name>.utm`.
