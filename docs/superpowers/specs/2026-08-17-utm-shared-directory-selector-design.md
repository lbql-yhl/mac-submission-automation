# UTM 共享目录选择器修复设计

## 背景

`utm-vm-clone` 的步骤 3 在共享目录页面找不到 `Choose/选择` 控件时，会在整个 UTM 编辑窗口搜索通用的 `新建…/New…` 按钮。当前界面中唯一命中的按钮属于左侧驱动器区域，脚本因此打开“新建驱动器”弹层，随后因不存在目录选择器而报 `directory picker sheet count=0`。

## 目标

- 只允许共享目录区域的语义控件打开目录选择器。
- 绝不点击左侧设备或驱动器区域的通用“新建…”按钮。
- 保留现有 `Choose/选择` 路径，并对目录选择器的异步出现做有界等待。
- 匹配不唯一或语义控件不存在时关闭失败，不使用坐标、视觉操作或直接修改 UTM 配置绕过验证。

## 设计

`unique_directory_picker_control()` 按以下优先级选择控件：

1. 唯一的 `Choose/选择` 按钮或菜单按钮。
2. 唯一的 `ADD_SHARED_LABELS`（`新建共享目录…/Add Shared Directory…`）按钮。
3. 其他情况抛出 `AXTargetError`。

删除对整个窗口中通用 `新建…/New…` 按钮的兜底。`configure_sharing()` 点击“添加”后做最多三轮有界重读；任一轮发现原生目录选择器即继续，否则才调用上述精确共享控件，再进入既有目录选择和严格读回流程。

## 测试与验收

- 回归测试同时提供共享目录语义按钮和全局“新建…”按钮，断言只返回共享目录按钮。
- 回归测试仅提供全局“新建…”按钮，断言关闭失败。
- 先运行测试并确认旧实现失败，再做最小实现使其通过。
- 运行 `tests/test_utm_1_ax.py` 的 pytest 与脚本断言。
- 使用 `gvby` 重跑步骤 3；成功后重跑 `utm-vm-clone` 总入口，要求输出 `UTM_CLONE_AND_INITIALIZE=verified`。
