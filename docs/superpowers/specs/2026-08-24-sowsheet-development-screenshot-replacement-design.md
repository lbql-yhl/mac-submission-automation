# SowSheet 研发截图替换设计

## 目标

将 SowSheet 当前待提交版本中 6.9 英寸 iPhone 截图栏位已经上传的美女截图全部移除，改为飞书 Base 中唯一匹配 SowSheet 记录的“研发截图”附件。替换完成并独立回读验证后停止，由用户自行提审。

## 精确范围

- 目标应用：SowSheet。
- 目标版本：当前已存在且唯一匹配的待提交版本，不创建或切换版本。
- 目标栏位：6.9 英寸 iPhone 截图栏位。
- 截图来源：飞书 Base 中唯一匹配 SowSheet 记录的“研发截图”附件，强制忽略“美女截图 链接”。
- 不操作其他应用、其他设备尺寸、构建、内购、版本信息或审核资料。
- 不点击 `Submit for Review`，不触发最终提审。

## 执行流程

1. 绑定同一精确 run、SowSheet 应用、当前待提交版本、VM、网络身份、SSH 身份和既有 Edge/CDP 会话。
2. 通过项目 Feishu OpenAPI 封装读取唯一匹配记录，确认“研发截图”恰好有一个合法 ZIP、PNG 或 JPEG 附件；记录非敏感的来源摘要、文件数量和文件哈希，不输出链接、Token 或真实资源 ID。
3. 在 App Store Connect Media Manager 中重新核验应用名、版本和 6.9 英寸栏位；确认栏位非空且现有截图属于本次要替换的旧截图集合。
4. 删除该栏位的全部旧截图。删除后重新读取页面，要求稳定计数为零；删除结果不明确时只做只读核验，不重复推测性删除。
5. 将“研发截图”附件解包或规范化为该栏位接受的纵向尺寸，保持原始顺序；上传整组图片。
6. 回读稳定截图计数，要求与研发源图片数量完全一致且不存在尺寸错误；同时核对上传后的图片集合摘要与准备好的研发图片集合一致。
7. 保持页面停留在 SowSheet 对应 Media Manager，停止操作并交还用户自行提审。

## 安全与失败处理

- 应用、版本、栏位、来源记录或删除控件任一不唯一时立即停止，不选择“最新”或近似对象。
- “研发截图”缺失、附件数量不是一个、文件无效、解包为空、图片多于栏位容量或方向不一致时，不删除旧截图。
- 删除旧截图后若上传失败，只在同一来源、同一栏位和同一会话内按 0/5/10 秒最多三轮恢复；不得改用美女截图或其他应用素材。
- 不重启 Edge，不重新登录，不切换应用，不提交审核。
- 不读取、打印或提交根 `.env`、`runtime/` 内容、密码、Token、真实资源 ID 或认证 URL。

## 验收标准

- 当前页面唯一绑定 SowSheet 当前待提交版本。
- 6.9 英寸 iPhone 栏位旧美女截图计数为零。
- 研发截图源合法且来源字段明确为“研发截图”。
- 上传后栏位稳定计数等于研发源图片数量，图片集合摘要一致，无尺寸错误。
- 未点击 `Submit for Review`，审核提交状态未被改变。
- 其他应用、版本、设备尺寸、构建与审核资料未被修改。
