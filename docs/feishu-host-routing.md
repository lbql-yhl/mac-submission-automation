# 飞书机器人宿主机设置说明

## 用途

多个宿主机机器人可以同时收到同一条飞书提审登记。每台机器人只接取 `使用的宿主机` 与本机配置完全一致的任务，其他任务静默忽略。

## 设置规则

1. 每台宿主机使用唯一且固定的名称。
2. 名称区分大小写，必须与飞书登记逐字一致。
3. 每台机器只修改自己的 `.env`，严禁复制其他机器的 `.env`、密钥或账号数据。
4. `FEISHU_BOT_HOST` 是 HTTP 监听地址，与任务宿主机名称无关，不要用它设置路由。

## 配置步骤

进入该宿主机上的项目目录，在现有 `.env` 增加或修改一行：

```env
SUBMISSION_HOST_MACHINE=<本机宿主机名称>
```

示例：

```env
# 海淋宿主机
SUBMISSION_HOST_MACHINE=海淋

# dev1 宿主机
SUBMISSION_HOST_MACHINE=dev1
```

不要同时保留两行 `SUBMISSION_HOST_MACHINE`。

保存后重启这台机器上**现有的**飞书机器人 supervisor，使新环境变量生效。若当前在前台运行，先正常停止原进程，再从项目目录启动：

```bash
python3 -u services/feishu_supervisor.py
```

若使用 launchd 或其他进程管理器，重启原有服务即可；不要额外启动第二个 supervisor。

## 安全检查

以下命令只打印宿主机名称，不会打印密钥：

```bash
python3 - <<'PY'
from services.feishu_bot import load_config

name = load_config().submission_host_machine
assert name, "SUBMISSION_HOST_MACHINE 未设置"
print(f"SUBMISSION_HOST_MACHINE={name}")
PY
```

运行自动化检查：

```bash
python3 tests/test_feishu_submission_parse.py
```

退出码为 `0` 且没有报错即为通过。

## 运行结果

| 飞书登记 | 本机行为 |
| --- | --- |
| `使用的宿主机` 与本机配置完全一致 | 创建 run、生成 `vm_name`、回复并按配置启动流程 |
| 指定其他宿主机 | 静默忽略，不创建 run、不回复、不启动流程 |
| 本机未设置 `SUBMISSION_HOST_MACHINE` | 安全失败，不启动任何提审登记 |
| `/提审 开始` 未附完整登记信息 | 不启动 |

例如所有机器人都收到 `使用的宿主机：dev1` 时，只有配置为 `dev1` 的机器人接取；配置为“海淋”或其他名称的机器人保持静默。

普通 Codex 对话不使用这条宿主机过滤。只有完整固定登记模板会触发提审路由判断。

## 交互卡片

- 故障卡和故障超时卡会显示该 run 的宿主机。
- 故障决定、通用用户确认、旧运行兼容提审确认回调和成功通知都会重新读取 run 的登记宿主机，并与本机 `SUBMISSION_HOST_MACHINE` 精确比较；通用确认只在技能正文明确要求业务决定时使用，用户点击即作为回复。新运行的 `utm-24` 使用自动自检授权，不等待确认回调。
- 只有匹配本机的卡片可以执行；宿主机缺失、不匹配或本机配置为空时，不修改 run、不唤醒执行器、不执行提审，只返回“非本机卡片，未执行任何操作”并记录审计日志。
- 按钮回传值不是宿主机身份依据，不能用修改按钮数据绕过 run 校验。

## 飞书登记模板

```text
@机器人

使用的宿主机：<目标宿主机名称>
应用名：<应用名称>
代理信息：<IP>:<端口>:<代理用户名>:<代理密码>
代码链接：<代码仓库链接>

开发者账号信息：
<国家>
<Apple ID 邮箱>
<Apple ID 初始密码>
<手机号> <短信接收链接>

银行信息（可选，可整体省略）：
ABA Routing Number：<ABA 路由号码，可留空>
Account Number：<银行账户号码，可留空>
```

银行区块可省略，两项银行号码也可留空；匹配宿主机仍会正常创建 run，无需为了启动流程提前准备银行号码。若到 `utm-20` 银行资料步骤为空，该技能会在立即、5 秒、10 秒三轮重新验证父页并读取两项；仍为空才以权威数据缺失发送最后故障卡，收到卡片处理回应后仍以同一 Notion 页实时重读为准。

## 故障检查

- 本机任务未接取：核对 `.env` 名称、飞书字段、大小写和首尾空格，并确认机器人已重启。
- 其他宿主机任务被接取：确认运行的是更新后的代码，并排查是否存在未重启的旧机器人进程。
- 同一任务被重复回复：检查是否启动了多个 supervisor，或多台机器是否误用了同一个宿主机名称。
- 配置为空：补充 `SUBMISSION_HOST_MACHINE` 后重启；不要绕过安全失败逻辑。
