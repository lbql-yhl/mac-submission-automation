# UTM-6

## 全局自动恢复与最后故障卡规则

本技能强制继承共享重复操作记忆：原生粘贴调用 `OP-NATIVE-PASTE`，浏览器 URL 调用 `OP-BROWSER-URL-NO-SCHEME`，Apple 电话/验证码调用 `OP-APPLE-PHONE-OTP`，固定 VM 密码调用 `OP-FIXED-PASSWORD-1234`，必须由用户决定的业务节点才调用 `OP-USER-CONFIRMATION`。不得在本技能内发明简化版或冲突步骤。可安全修复的故障必须做满三轮“诊断→实际修复→独立复验”；只有不可逆动作、不能安全重复写入或外部不可修复状态，才改做三轮独立只读复核。少于三轮时运行时拒绝发卡。

执行任何命令前，在项目根目录运行 `eval "$(python3 scripts/preflight.py --project-only --emit-shell)"`，取得当前机器的动态路径。必须先完整遵守 [`../_shared/AUTOMATION_CONTRACT.md`](../_shared/AUTOMATION_CONTRACT.md)：固定顺序是自动诊断、自动修复、自动复验，只有智能体确实无法修复时才允许发送飞书故障卡。

- 正常成功路径连续自动执行，不发送故障卡，不等待用户确认或普通聊天回复。
- 可逆误点先回到本技能矩阵列出的最近验证锚点，作废旧坐标，等待至少 3 秒并用最新截图重做当前最小动作；成功后记录 `GUI_RECOVERY=verified` 并继续。
- SSH、API、文件和页面瞬态错误按共享合同有界恢复；不可逆动作只执行一次，结果不明时只读查询同一 attempt，禁止盲目重做。
- 只有恢复预算穷尽或只读证明为外部不可修复状态，才记录 `AUTO_RECOVERY_ATTEMPTS`、`AUTO_RECOVERY_ACTIONS`、`AUTO_RECOVERY_RESULT=exhausted|unrepairable` 和最后验证锚点。
- 自动恢复穷尽后，使用下列最后出口；`--unrepairable` 只允许用于 CAPTCHA、账号锁定、权威数据缺失、权限/所有权冲突或不可逆结果仍不明确，不能绕过可执行的恢复：

```bash
python3 services/feishu_bot.py notify-fault \
  --run-id '<current-run-id>' \
  --chat-id '<original-chat-id>' \
  --stage 'utm-6:<fault-stage>' \
  --fault '<non-sensitive-fault>' \
  --suggested-action '<safe-next-action>' \
  --failure-action '自动恢复穷尽后暂停副作用并等待故障卡决定' \
  --evidence '<non-sensitive-evidence>' \
  --completed-steps '<verified-completed-steps>' \
  --recovery-skill 'utm-6' \
  --recovery-attempts '<actual-count-at-least-3>' \
  --recovery-actions '<diagnose,repair,reverify>' \
  --recovery-result '<exhausted|unrepairable>'
python3 services/feishu_bot.py wait-decision \
  --run-id '<current-run-id>' --decision-kind fault --timeout-seconds 3600
```

规则：`--recovery-result unrepairable` 必须同时追加 `--unrepairable`；恢复穷尽的 `exhausted` 分支不得追加该参数。两种分支都必须填写真实的恢复次数和动作，不能把占位符原样执行。

故障卡仍固定保留 `stop`、`manual_continue`、`retry_skill` 三个决定及稳定 UUID/首次送达后一小时超时规则。当前执行器收到继续决定后立即重读同一精确现场；已验证步骤只有在证据仍成立时才跳过。故障卡是最后恢复出口，不是正常确认节点。

## 本技能自动恢复矩阵

| 故障点 | 自动诊断、修复和复验 | 最后发卡边界 |
|---|---|---|
| 出口 IP 请求失败/不符 | 先重试三个独立 IPv4 查询；再检查同一 Clash profile、进程和 Tun，自动重新选择/重启一次后复验 | 仍不符且代理源唯一时才 `exhausted` |
| `.zshrc` 缺行/重复 | 保存 before，只对固定管理区块原子替换，source 后逐项回读 | 失败则恢复 before 并发卡 |
| 环境运行值不符 | 重开一次登录 shell，核对命令路径和变量；不得靠当前非登录 shell 误判 | 三轮安全修复且每轮独立核对后仍不一致才发卡 |
| SSH 失败 | 同一 VM 自动恢复三轮 | 恢复耗尽才发卡 |

## SSH 全自动约束

- 直接继承 `utm-clash` 的同一精确 VM/IP、`<vm_name>` 和 `SSH_KEY_AUTH=verified`；只执行一次 `BatchMode=yes` 身份检查，不重复配置 SSH。
- SSH 检查失败时自动刷新同一 VM 的 IP、检查 Remote Login/端口并用固定 `1234` 恢复宿主机现有公钥；不得向用户索取密码、SSH Key 或 IP。
- SSH 自动恢复仍失败时记录 `SSH_AUTO_RECOVERY=blocked`，先按 `utm-6-ssh-auto-recovery` 记录故障阶段并执行本技能自动恢复矩阵；恢复穷尽后才发送最后故障卡并等待当前执行器处理决定；代理出口不匹配使用独立的 `utm-6-proxy-egress` 故障阶段，不得混同为 SSH 故障。

## 1. Verify proxy egress

Resolve `expected_proxy_ip` from the current run's `submission_data.proxy.host` in `runtime/feishu-runs.json`. If the current run is no longer in the cache, use the `server` in the `socks5.yml` generated by `utm-5` for this same run, after confirming the VM name; never use the Feishu desktop app. Do not print proxy credentials.

Validate the value on the host with `ipaddress.IPv4Address` and require canonical text before passing it as one positional argument; never interpolate an unchecked runtime value into remote shell source. Bind the inherited private key explicitly:

```bash
private_key="${SUBMISSION_SSH_PRIVATE_KEY}"
expected_proxy_ip="$(<exact same-run API reader output>)"
python3 - "$expected_proxy_ip" <<'PY'
import ipaddress, sys
value = sys.argv[1]
parsed = ipaddress.IPv4Address(value)
if str(parsed) != value:
    raise SystemExit("non-canonical proxy IPv4")
PY
ssh -o BatchMode=yes -o IdentitiesOnly=yes -i "$private_key" \
  -o ConnectTimeout=5 '<vm_name>@<vm-ip>' \
  /bin/zsh -s -- "$expected_proxy_ip" <<'EOF'
set -euo pipefail
expected_proxy_ip="$1"
egress_ip="$(/usr/bin/curl -4fsS --max-time 20 https://api.ipify.org)"
printf 'EXPECTED_PROXY_IP=%s\n' "$expected_proxy_ip"
printf 'GUEST_EGRESS_IP=%s\n' "$egress_ip"
[ "$egress_ip" = "$expected_proxy_ip" ] || { echo 'proxy egress mismatch' >&2; exit 20; }
echo 'PROXY_EGRESS=verified'
EOF
```

Only exact equality is success. If the request fails or differs, stop before changing `~/.zshrc` and automatically recover the same proxy path: re-read the exact run proxy IP, verify the selected guest `socks5.yml` and fixed Clash switches without printing credentials, test the local SOCKS listener, restart only Clash Verge once when its process/config is stale, then repeat the IPv4 request at 5/15/30 seconds. A matching result records `PROXY_EGRESS_RECOVERY=verified` and continues automatically. Only three verified mismatches, an unreachable registered proxy, or an ownership/config conflict is allowed to record `AUTO_RECOVERY_RESULT=exhausted|unrepairable` and use the file-opening `utm-6-proxy-egress` last fault card. Card continuation restarts this same diagnosis; it never authorizes modifying `~/.zshrc` before exact equality.

## 2. Set guest environment variables

Replace `<vm_name>` with the current four-letter VM name. Manage one exact delimited block instead of appending independent lines. Before mutation, require zero complete blocks or exactly one begin/end pair in the correct order; duplicate or unterminated markers stop without writing.

```bash
ssh -o BatchMode=yes -o IdentitiesOnly=yes -i "$private_key" \
  '<vm_name>@<vm-ip>' '/bin/zsh -s' <<'EOF'
set -euo pipefail
zshrc="$HOME/.zshrc"
before="$(mktemp "$HOME/.zshrc.utm6.before.XXXXXX")"
chmod 600 "$before"
if test -e "$zshrc"; then cp -p "$zshrc" "$before"; else : >"$before"; fi
restore() {
  /usr/bin/python3 - "$before" "$zshrc" <<'PY'
from pathlib import Path
import os, sys, uuid
before, target = map(Path, sys.argv[1:])
payload = before.read_bytes()
tmp = target.with_name(f".{target.name}.{uuid.uuid4().hex}.restore")
with tmp.open("xb") as handle:
    handle.write(payload); handle.flush(); os.fsync(handle.fileno())
tmp.chmod(0o600)
os.replace(tmp, target)
PY
  printf 'ZSHRC_ROLLBACK=verified\n'
}
trap 'rc=$?; if (( rc != 0 )); then restore; fi; rm -f "$before"; exit $rc' EXIT
/usr/bin/python3 - "$zshrc" <<'PY'
from pathlib import Path
import os, sys, uuid
path = Path(sys.argv[1])
begin = "# >>> submission-automation utm-6 >>>"
end = "# <<< submission-automation utm-6 <<<"
block = "\n".join((
    begin,
    'export PATH="/usr/local/opt/ruby/bin:$PATH"',
    'export PUB_HOSTED_URL="https://pub.flutter-io.cn"',
    'export FLUTTER_STORAGE_BASE_URL="https://storage.flutter-io.cn"',
    'export PATH="$PWD/flutter/bin:$PATH"',
    'export PATH="/Users/<vm_name>/Downloads/tools/flutter/bin:$PATH"',
    end,
))
text = path.read_text(encoding="utf-8") if path.exists() else ""
if text.count(begin) != text.count(end) or text.count(begin) > 1:
    raise SystemExit("managed block ambiguous")
if begin in text:
    start, finish = text.index(begin), text.index(end) + len(end)
    text = text[:start].rstrip("\n") + "\n" + block + text[finish:]
else:
    text = text.rstrip("\n") + ("\n\n" if text else "") + block + "\n"
payload = text.encode()
tmp = path.with_name(f".{path.name}.{uuid.uuid4().hex}.tmp")
with tmp.open("xb") as handle:
    handle.write(payload); handle.flush(); os.fsync(handle.fileno())
tmp.chmod(0o600)
os.replace(tmp, path)
if path.read_bytes() != payload:
    raise SystemExit("zshrc readback mismatch")
print("ZSHRC_WRITE=atomic_verified")
PY
/bin/zsh -lic '
  test "$PUB_HOSTED_URL" = https://pub.flutter-io.cn
  test "$FLUTTER_STORAGE_BASE_URL" = https://storage.flutter-io.cn
  case ":$PATH:" in *":/usr/local/opt/ruby/bin:"*) ;; *) exit 21;; esac
  case ":$PATH:" in *":/Users/<vm_name>/Downloads/tools/flutter/bin:"*) ;; *) exit 22;; esac
'
trap - EXIT
rm -f "$before"
printf 'ZSHRC=verified\n'
EOF
```

## 3. Verify `~/.zshrc`

Run a second, fresh SSH login shell. Require each managed marker and line exactly once, no old duplicate of any managed export outside the block, and the runtime values below:

```bash
set -euo pipefail
for line in \
  'export PATH="/usr/local/opt/ruby/bin:$PATH"' \
  'export PUB_HOSTED_URL="https://pub.flutter-io.cn"' \
  'export FLUTTER_STORAGE_BASE_URL="https://storage.flutter-io.cn"' \
  'export PATH="$PWD/flutter/bin:$PATH"' \
  'export PATH="/Users/<vm_name>/Downloads/tools/flutter/bin:$PATH"' \
  '# >>> submission-automation utm-6 >>>' \
  '# <<< submission-automation utm-6 <<<'; do
  [ "$(/usr/bin/grep -Fxc "$line" "$HOME/.zshrc")" -eq 1 ]
done
source "$HOME/.zshrc"
[ "$PUB_HOSTED_URL" = 'https://pub.flutter-io.cn' ]
[ "$FLUTTER_STORAGE_BASE_URL" = 'https://storage.flutter-io.cn' ]
case ":$PATH:" in *":/usr/local/opt/ruby/bin:"*) ;; *) exit 21 ;; esac
case ":$PATH:" in *":/Users/<vm_name>/Downloads/tools/flutter/bin:"*) ;; *) exit 22 ;; esac
case ":$PATH:" in *":$PWD/flutter/bin:"*) ;; *) exit 23 ;; esac
echo 'ZSHRC=verified'
```

## Completion

Report only the VM name, `GUEST_EGRESS_IP`, exact IP-match result, `PROXY_EGRESS=verified`, `ZSHRC_WRITE=atomic_verified`, `ZSHRC=verified`, and the required variable/PATH checks. On any post-write failure require the same-attempt before restoration and `ZSHRC_ROLLBACK=verified` before a card. Never report proxy username or password. Do not continue until all success markers are present; then record `UTM_6=verified`.
